# What the launch day taught the harness (2026-09-06)

Status: all nine implemented the same day (`mh frame`, stale guard in `lint --rendered`, `render --format all --out-dir`, audibility / fade-in / ramp lint / head profile in `mh audio`, `mh still`, `mh srt`, `mh deliver`, size and bitrate in the render log, `MH_PROJECT` + last project, `{ dwell }` on legs). Pinned by `src/launch-day.test.ts`.

Source: the second film session (cold open, five brand marks, typing sfx tried and dropped,
music retimed, shelf rebuilt, thumbnails, Shorts cover, SRT, CDN and YouTube upload, landing
A/B). Ordered by how often it cost a round.

## 1. Frames on demand

`mh check` renders a sampled set, and the frame I wanted was never in it (`turn+40` did not
exist, `turn+45` did). Twice I fell back to `ffmpeg -ss` on the film with `mh resolve` for the
seconds.

- `mh frame <addr> [--format all] [--crop x,y,w,h]`: render exactly that frame (or list) from
  the bundle, print the path. `<addr>` is anything `resolve` accepts.
- `mh frames` prints the addresses it wrote, so a guess is never needed.

## 2. Rendered lint must know its frames are stale

After a source edit `mh lint --rendered` reported 8 errors from the previous run's frames.
Compare the run's bundle hash with the current one and refuse (or re-render the touched
scenes) instead of lying.

## 3. Render wants `--format all` too

`check`, `frames`, `lint`, `probe` take it; `render` does not, so every delivery is two
commands plus two copies. `render --format all` and `--out-dir` that names files by format.

## 4. Audio checks for short cues

- A 150 ms key under a bed was invisible to the 250 ms rms window ("rms before 0.176 after
  0.170"). Per cue: high-pass the mix at 2 kHz and compare the peak in a 60 ms window at the
  cue against the 200 ms before it; print the delta in dB. That is the number that decided
  audible or not, and I computed it by hand three times.
- A bed with `gain: 0` and a ramp reports "NOTHING AUDIBLE" at its start. A cue whose first
  ramp starts at its own `at` is a fade-in, not silence.
- A ramp resolved before film start (`product - 9s` after the opening was cut to 5 s) was
  silently clamped. Warn.
- Per music file, print the rms of the first 3 s in 100 ms steps (or "audible from X s"), so
  `trim` for a cold start is read off, not searched.

## 5. Stills are part of the film

Thumbnails, the Shorts cover and the OG image were `remotionb still` plus `magick` by hand.
`mh still <id|all> [--format] [--jpg --width 1280] [--sheet]` renders every `<Still>` the
project registers, converts, and sheets them, with the same lint (overflow, safe zone,
wrap) as frames. The `vs` split rendered text off the panel edge; a lint would have caught it.

## 6. Subtitles from the timeline

`mh srt [--lang en] [--out]`: one entry per scene with `text`, film times from the compile.
Scenes without text can carry `caption` in the config for the SEO line ("Bo is mapping your
course: 12 files, 5 topics"). Written by hand today as a 15-line bun script.

## 7. Deliver

`mh deliver --to r2://pub/video/<name>/ --youtube ...` is too much. But `mh deliver --out
docs/.../deliverables` that copies films, stills, srt, writes a README with sizes, durations,
sha and the chapter list from the timeline, and a `.gitignore` for the mp4 files, is the
thing I did by hand in four commands.

## 8. Render log should print size and bitrate

The film dropped from 50 MB to 9 MB after the grain-heavy opening was cut and I spent a round
checking whether the render was broken. One line per segment and per film: frames, seconds,
MB, kbit/s.

## 9. Config ergonomics

- `mh` from the wrong cwd fails with "no harness.config.ts in <cwd>" even with `--project .`
  because cwd resets between shell calls. Honour `MH_PROJECT` and remember the last project
  in `~/.mh/last`, print which one was used.
- Hover legs (`key?`) landed this session. Next: `["probe.optD", "opt-d?", {dwell: 10}]` so a
  change of mind can rest before it moves.

## What was good

`--remix` (2 s for a music change), `check --scene x --format all` as the per-edit command,
`resolve` for every chapter time, segment cache by part source (opening edits never touched
the product half), `sfx` attack/tail table (caught the 108 ms attack on the first key cut),
data-lint="no-collision" for designed overlaps.
